## 使用方式

1. `Project Plan` 保留 Project Tracker 的維護工作、狀態與 20 週排程。指定維護人並補實際計畫日期；沒有承諾的日期保持空白。維護計畫不表示版本已上線。
2. `版本紀錄` 每個平台／元件／build 各列一筆。紀錄 ID 建立後保持不變。補版本、變更、測試、程式 SHA／tag、依據及負責人；確認發布後才填實際發布日並改為「已發布」。
3. `變更依據` 是最近提交的追溯快照，可補充來源。提交日期不當作發布日。
4. 新增列時延伸 Excel 表格及驗證規則。版本統計涵蓋前 500 筆（第 9–508 列）；超過時同步延伸公式範圍。每次儲存後查看「已發布缺日期」，有缺項就補齊。
5. 關閉 Excel 後，在獨立文件分支提交並開 PR。由一位維護人順序編輯，避免二進位檔案衝突。保留其他人的未提交修改。

## GitHub 與 SVN 同步

PR 合併後，從確定的 Git commit 取出這份 Excel，計算 SHA-256，再複製到已確認的 SVN 對應目錄。檔案旁的同步 manifest 記錄來源倉庫、文件 Git commit 與 SHA-256。SVN 提交成功後讀回檔案驗證，另存含 SVN revision 的回執。

兩端無法原子提交。GitHub 成功而 SVN 未成功時保持「SVN 待同步」，重試同一份檔案即可。不要把 Excel 自身 hash、文件自己的提交 SHA 或同批 SVN revision 寫回 Excel，以免循環修改。實際認證、路徑對應及回執由內部管控工具管理，本檔不宣稱同步已完成。
